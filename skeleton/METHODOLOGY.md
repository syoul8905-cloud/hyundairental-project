# 5인 에이전트 협업 프로젝트 방법론 스켈레톤 (Multi-Agent Collaboration Framework)

본 스켈레톤은 복잡한 현업 비즈니스 소프트웨어 구축 및 고도화 작업을 5개 특화 페르소나(PM, 엔지니어, UI/UX, 실무자, 감사)의 다각적 관점으로 분석하고, 사용자 심층 인터뷰를 거쳐 최적의 실용적 시스템을 도출하는 표준 방법론입니다.

---

## 1. 5개 핵심 페르소나 구조 (The 5 Core Personas)

| 역할 | 페르소나 정의 | 핵심 관심사 | 관점의 가치 |
| :--- | :--- | :--- | :--- |
| **1. 프로젝트 매니저 (PM)** | 총괄 기획자 및 오케스트레이터 | 일정, 마일스톤, 우선순위, 범위(Scope) 통제 | 목표의 일관성 유지 및 기한 내 고품질 인도 |
| **2. 소프트웨어 엔지니어** | 기술 아키텍트 및 개발자 | DB 구조, API 연동, 양방향 동기화, 시스템 안정성 | 확장 가능하고 장애 없는 기술 기반 구축 |
| **3. UI/UX 전문가** | 사용자 경험 및 인터페이스 디자이너 | 현장 모바일 환경, 원클릭 조작, 정보 가독성 | 현장 운전/배송 기사와 사무직의 조작 편의 극대화 |
| **4. 게으른 실무자 (Lazy Practitioner)** | 극단적 편의성 추구 현업 담당자 | 수작업 제거, 1초 컷 자동화, 타이핑 최소화 | 시스템 실사용률(Adoption Rate)을 100%로 끌어올림 |
| **5. 감사 (Auditor)** | 리스크 관리 및 내부 통제관 | 데이터 위변조 방지, 이력 추적, 자산 분실 통제 | 법적/재무적 리스크 및 인적 오류 원천 차단 |

## 2. 4단계 협업 및 프로젝트 수행 프로세스

### 1단계: 다각적 현황 분석 (Multi-Angle Audit)
* 5개 페르소나가 각자의 시각에서 기존 데이터와 코드를 분해 분석.
* 병목점(Bottleneck), 보안 취약점, 사용성 저해요소, 기술적 한계점을 동시에 도출.

### 2단계: 교차 검증 인터뷰 (Cross-Perspective Interview)
* 페르소나별로 클라이언트에게 확인해야 할 핵심 의사결정 질문 취합.
* 실무자의 편의 요구 vs 감사의 통제 요구 간의 균형점(Trade-off)을 질문을 통해 도출.

### 3단계: 통합 구현 설계 (Master Implementation Plan)
* 인터뷰 답변을 토대로 단계별(P0 즉시 적용 ~ P2 고도화) 실행 계획 수립.
* 프론트엔드, 백엔드, DB, 외부 연동(구글시트, 맵/내비 API, 알림톡) 아키텍처 명세화.

### 4단계: 점진적 배포 및 학습 (Continuous Learning & Skeleton Update)
* 핵심 기능을 신속히 릴리즈(Quick-Win)하고 피드백을 수집.
* 도출된 성공 패턴과 도메인 특화 룰을 스켈레톤 및 룰셋으로 지속 학습/저장.

## 3. 배송 스케줄 관리 도메인 특화 체크리스트

1. **ERP/스프레드시트 연동성**: ERP 원본 파일 드롭 시 자동 파싱 및 기존 일자 데이터와의 교차 보강.
2. **현장 모바일 인터랙션**: 주소 터치 시 Tmap/네이버지도 내비 즉시 길안내, 고객 전화 원터치 연결.
3. **감사 추적성**: 누가, 언제 배송 상태를 완료/변경했는지 타임스탬프 및 담당자 자동 로깅.
4. **일정/메모 분리**: 단순 메모와 배송 트랜잭션을 분리하여 데이터 무결성 보장.
